# Implement camera detection result ingestion from edge/YOLO pipeline

Labels: `enhancement`

> *This was generated by AI during triage.*

## Context

Proposal and Progress I both require ParkPilot to persist camera-derived parking data, not just display live video.

Relevant requirement evidence:

- Proposal: ParkPilot should stop discarding raw detection signals and restructure the database to log timestamped slot-level events.
- Proposal scope: the edge device data pipeline should capture granular, timestamped parking events for individual spots and expose the data through REST APIs.
- Progress I F1: the system receives parking snapshots and slot state changes from four connected camera streams or MQTT, stores event history, serves live lot status, calculates analytics KPIs, and exposes system health data.
- Progress I URS-06: the system shall continuously receive and save slot state-change events into an append-only database.

Current code already has the backend storage and API foundation:

- `POST /api/analytics/camera/events`
- `POST /api/analytics/heartbeat`
- `ParkingSnapshot`
- `ParkingSnapshot2`
- `ParkingEventLog`
- `DeviceHealth`

However, the current repository does not contain the YOLO/OpenCV inference pipeline. `services/parking_service.py` only proxies image inference requests to an external edge server at `http://10.41.11.21:9696`.

## Problem

Live camera video can now be viewed locally via HLS proxying, but video viewing alone does not persist analytical data. Dashboard analytics become real only when the edge/YOLO detector sends structured detection results into the backend.

Without this feature, the system can show live video but cannot reliably populate:

- current available/occupied spaces
- slot-level event history
- spatial heatmaps
- occupancy trends
- dwell-time calculations
- system health based on live edge heartbeat

## Desired Flow

```text
Camera stream
-> Orange Pi / edge YOLO detector
-> structured JSON detection result
-> FastAPI ingestion endpoint
-> PostgreSQL snapshots and event logs
-> dashboard / analytics / chatbot APIs
```

## Proposed Payload

The edge service should send or expose data matching the existing `CameraEventPayload` shape:

```json
{
  "lot_id": "CAMT_01",
  "total_spaces": 30,
  "available_spaces": 12,
  "occupied_spaces": 18,
  "confidence": 0.95,
  "processing_time_seconds": 0.14,
  "events": [
    { "spot_id": "A01", "status": "occupied" },
    { "spot_id": "A02", "status": "free" }
  ]
}
```

## Acceptance Criteria

- The system can ingest real structured detection results from the edge/YOLO pipeline.
- Parking Area 1 and Parking Area 2 update `ParkingSnapshot` / `ParkingSnapshot2` with current availability.
- Slot-level changes append rows to `ParkingEventLog`.
- Board and camera status update through `POST /api/analytics/heartbeat`.
- `GET /api/analytics/current?lot_id=CAMT_01` returns current real camera-derived values.
- `GET /api/analytics/heatmap?lot_id=CAMT_01` returns event-derived spot data.
- `GET /api/analytics/health` reflects fresh online/offline state from the board.
- If the edge detector is unreachable or returns invalid data, the backend logs the failure and does not corrupt stored analytics data.

## Implementation Notes

There are two acceptable integration paths:

1. Preferred: the edge/YOLO service posts results directly to the backend:

```text
POST /api/analytics/camera/events
POST /api/analytics/heartbeat
```

2. Alternative: the backend polls an edge JSON endpoint, maps the result, and reuses `AnalyticsService.process_camera_events()`.

Avoid making the frontend call the Orange Pi directly for detection data or control commands. The frontend should continue reading analytics through the backend API.
